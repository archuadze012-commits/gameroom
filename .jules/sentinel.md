## 2026-11-04 - [Fix timing attack vulnerability in API routes]
**Vulnerability:** Direct string comparison (`!==`) was used to compare the provided `authorization` header with the expected `CRON_SECRET` in multiple cron API routes (`src/app/api/admin/cron/reengage/route.ts`, `src/app/api/admin/cron/unban-expired/route.ts`, `src/app/api/admin/cron/expire-highlights/route.ts`).
**Learning:** Standard string comparison operators in JavaScript (`==`, `===`, `!=`, `!==`) compare strings character by character and return as soon as a mismatch is found. This variable execution time can allow an attacker to guess a secret token byte-by-byte using a timing attack.
**Prevention:** Always use constant-time comparison functions, such as `crypto.timingSafeEqual` from the `node:crypto` module, when comparing security-sensitive strings (e.g., API keys, auth tokens, secrets). Additionally, ensure the lengths of the buffers being compared match before calling `timingSafeEqual` to avoid errors or other timing leaks.
